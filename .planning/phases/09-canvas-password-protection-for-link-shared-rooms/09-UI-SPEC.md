## Component Inventory

### New UI surfaces for this phase

#### Surface 1: Password Gate (full-screen centred card)

Triggered when: `joinState === 'password-required'`

Layout: Reuses the exact pattern from the existing `'private'` gate (lines 66–77 of `page.tsx`).

```
<div className="flex min-h-screen flex-col items-center justify-center gap-4 bg-background">
  <KeyRound className="h-12 w-12 text-muted-foreground" />
  <h1 className="text-xl font-semibold text-foreground">This board is password protected</h1>
  <p className="text-sm text-muted-foreground">Enter the password to join.</p>
  <div className="flex flex-col gap-3 w-full max-w-xs">
    <Input type="password" placeholder="Password" ... />
    [inline error text — "Incorrect password" — text-xs text-destructive, visible on 401 retry]
    <Button variant="default" className="w-full">Join Board</Button>
  </div>
</div>
```

States:

- **Default:** Icon + heading + subtext + input + button
- **Wrong password:** Input gains shake animation (`animate-shake`), inline `"Incorrect password"` text below input in `text-destructive`
- **Submitting:** Button shows `<Loader2 className="h-4 w-4 animate-spin mr-2" />` + disabled state

Shake animation — add to `globals.css` under `@layer base`:

```css
@keyframes shake {
  0%,
  100% {
    transform: translateX(0);
  }
  20% {
    transform: translateX(-6px);
  }
  40% {
    transform: translateX(6px);
  }
  60% {
    transform: translateX(-4px);
  }
  80% {
    transform: translateX(4px);
  }
}
.animate-shake {
  animation: shake 0.35s cubic-bezier(0.36, 0.07, 0.19, 0.97) both;
}
```

Animation applied to the `<Input>` element on 401 retry. Class added via `useState` toggled after 350ms to allow replays.

## Interaction Contract

### Password Gate Flow

1. `joinRoom()` called on page load (and on submit with password)
2. 401 response with no prior password attempt → `setJoinState('password-required')`
3. 401 response after submitting password → apply `animate-shake` to input, display `"Incorrect password"` below input, re-enable button
4. On submit: disable button, show Loader2 in button, call `joinRoom()` with `{ password: enteredValue }` in body
5. On success: `sessionStorage.setItem('pw-verified-{slug}', '1')`, proceed to `'joined'` state
6. On page load: check `sessionStorage.getItem('pw-verified-{slug}')` — if present, include sentinel in first join body to bypass gate without re-prompting

### Settings Popover Password Flow

1. On popover open: GET `/api/rooms/:slug` returns `hasPassword: boolean` — render correct sub-state
2. Set: PATCH `/api/rooms/:slug` `{ password: string }` → optimistic `hasPassword: true` + toast "Password set" + rollback on failure
3. Change: PATCH `/api/rooms/:slug` `{ password: string }` → toast "Password updated" + rollback on failure
4. Remove: PATCH `/api/rooms/:slug` `{ password: null }` → optimistic `hasPassword: false` + toast "Password removed" + rollback on failure

### Accessibility

- Password gate `<Input>` has `aria-label="Room password"` and `aria-describedby` pointing to the error message element (rendered with `role="alert"` when visible)
- "Join Board" button has `aria-busy="true"` while submitting
- `KeyRound` icon in badge is `aria-hidden="true"` (text label "Protected" carries the meaning)
- Settings section heading uses `<h4>` to maintain heading hierarchy within the popover
